# Smart Security System

Стенд ВКР по отказоустойчивой связи IoT-устройств. Две ESP32, локальное управление по BLE и удалённый доступ через Java-облако.

- **ESP32-SS** — охрана, сирена, расстояние, свет, AHT20+BMP280.
- **ESP32-CL** — климатический узел с AHT20+BMP280.
- **Flutter** — BLE-настройка Wi-Fi и локальное управление, аккаунт и удалённое управление в одном приложении.
- **Java 21 / Spring Boot / PostgreSQL** — аккаунты, устройства, команды с подтверждением, история тревог. HTTPS через Caddy.

Плата опрашивает облако примерно раз в 3 секунды для команд. Показания отправляются только при действующей подписке открытого экрана устройства; подписка истекает через 15 секунд без обновления. Тревоги передаются независимо от зрителей, сохраняются во flash ESP32 до подтверждения и записываются в PostgreSQL без дубликатов.

## Запуск

1. [Развернуть облако](backend/README.md) на сервере с доменом и HTTPS.
2. [Прошить обе платы](firmware/README.md) с новой таблицей разделов.
3. [Обновить Flutter-приложение](mobile/README.md), войти в облако, подключиться к каждой плате по BLE и настроить Wi-Fi.
4. Проверить остановку телеметрии, отключение сети, повторную доставку тревог и просроченные команды по [сценариям проверки](backend/README.md#проверка-на-стенде).

## Границы текущей реализации

Нет передачи между ESP32, резервного сервера Ubuntu, DS3231, RabbitMQ и мобильных push-уведомлений из облака при закрытом приложении. Они остаются отдельными этапами исследования. Уже реализована ограниченная постоянная очередь из 64 тревог на каждой плате и повторная доставка при восстановлении облака. История обычной телеметрии во время отсутствия зрителя не ведётся.

Автоматические проверки: `mvn clean verify` в backend, `flutter analyze` и `flutter test` в mobile; обе конфигурации ESP-IDF 5.5.6 собираются отдельно.
