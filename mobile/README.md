# Охрана ESP32

Flutter-клиент связывается с первой ESP32 напрямую по BLE. Он показывает состояние охраны и сирены, передаёт команды и принимает показания и события от платы.

## Проверка на стенде

1. Открой терминал ESP-IDF 5.5 в Windows. В каталоге `firmware` собери и прошей первую ESP32, подставив её COM-порт. Отдельный `sdkconfig` применит настройки NimBLE из `sdkconfig.defaults`, даже если в каталоге уже есть старая конфигурация.

   ```powershell
   idf.py -B build/ble -D "SDKCONFIG=$PWD/build/ble/sdkconfig-ble" -p COM3 flash monitor
   ```

2. На Mac открой каталог `mobile` после клонирования репозитория. Подключи физический iPhone, укажи команду подписи для Runner в Xcode и выбери iPhone при запуске. [Настройка iOS для Flutter](https://docs.flutter.dev/platform-integration/ios/setup)

   ```sh
   flutter doctor -v
   flutter pub get
   flutter run
   ```

3. Нажми **Найти ESP32** и выбери **ESP32-SS**. При первом сопряжении введи в системном диалоге шестизначный код из строки `BLE pairing PIN` в Serial Monitor (115200 бод). Ключи сопряжения хранятся в NVS платы.
4. Проверь переключатели охраны и сирены. Для проверки событий поставь плату под охрану, поднеси предмет к сонару ближе порога и посвети на фоторезистор. Приложение покажет события в списке. Для системных уведомлений нажми **Разрешить уведомления телефона**.

На Android приложение при поиске запрашивает доступ к ближайшим устройствам. На Android 11 и более ранних версиях для сканирования используется разрешение геолокации. Для проверки BLE используй физический телефон.

Журнал приложения показывает до 30 событий за сеанс. Системные уведомления формируются, пока приложение получает данные по активной BLE-связи. Проверку удобно начинать с открытым приложением.

## Сервис GATT

| UUID | Назначение |
| --- | --- |
| `d91fc001-cc92-4e99-9c67-2f7396311bce` | Сервис охраны |
| `d91fc002-cc92-4e99-9c67-2f7396311bce` | Команды, запись с ответом |
| `d91fc003-cc92-4e99-9c67-2f7396311bce` | Состояние, чтение и уведомления GATT |

Доступ к данным и командам требует шифрованного соединения с подтверждённым PIN. Плата обслуживает одного BLE-клиента одновременно.

Команда занимает два байта `[0x01, код]`. Коды `1` и `2` снимают и ставят на охрану. Коды `3` и `4` выключают и включают сирену.

Состояние занимает 18 байт. Все двухбайтовые поля передаются в little-endian.

| Смещение | Данные |
| --- | --- |
| 0 | Версия протокола, `0x01` |
| 1 | Флаги от младшего бита к старшему: охрана, сирена, малое расстояние, свет, перегрев |
| 2 | Расстояние в десятых долях сантиметра, `uint16` |
| 4 | Освещённость в единицах АЦП, `uint16` |
| 6 | Температура в десятых долях °C, `int16` |
| 8 | Влажность в десятых долях процента, `uint16` |
| 10 | Давление в десятых долях гПа, `uint16` |
| 12, 14, 16 | Счётчики пересечений порогов дистанции, света и температуры, `uint16` |

Недоступные показания кодируются как `0xffff` для беззнаковых полей и `-32768` для температуры. Счётчики работают по модулю 65536 с момента запуска платы. При получении пакета приложение показывает одно событие на каждый изменившийся счётчик. При новом подключении оно начинает сравнение с текущего состояния платы.
